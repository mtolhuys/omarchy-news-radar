# Omarchy News Radar 0.5.8

Plugin updates now follow the plugin's declared release version rather than the repository's latest commit. Forge collector fixes, documentation edits, and other same-version changes therefore remain invisible to desktop installations.

The update checker reads both committed manifests through bounded Git objects, requires the exact Radar plugin identity and a strict three-part release version, and reports an update only when the fetched version is greater than the installed version. A dirty checkout, missing official updater, or divergent history blocks only that real newer release.

After Omarchy's official updater completes, Radar verifies that the installed release version reached or exceeded the offered version. It deliberately does not require one transient commit SHA, so a same-version server commit landing between inspection and apply cannot create a false failure.

This release also contains the production collector safeguards developed after 0.5.7: bounded marketplace catalog growth capacity, saturated-ledger addition retention, and networkless last-known-good degraded publication. These server paths do not create later client updates unless a future manifest explicitly declares a newer release.
