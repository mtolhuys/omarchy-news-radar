# Omarchy News Radar 0.5.11

This patch fixes Core news stories reappearing as unread after they were dismissed.

Two shipped behaviours combined to destroy reading decisions. The rolling 500-event ledger evicts official news when marketplace release volume crowds it out — the public edition on 22 September 2026 carried 480 plugin releases against five news rows, an eleven-day news window. The collector deliberately re-emits every Omarchy News item inside the rolling window on each collect so an eviction can rematerialize Core stories, and event identity is deterministic, so the story returns under the same ID. Meanwhile the client pruned read overrides to the current reading feed on every reading action. Plugin dismissals survived eviction because the `setup-news` companion carries plugin releases and retirements; official news has no companion, so its dismissals were deleted outright. Dismiss, evict, prune, rematerialize — and the story came back unread, every cycle.

A reading decision is now retained when its story is absent from the current edition. The override map keeps its existing 6,000-entry bound: decisions for stories in the current reading feed are always kept, and unreachable entries are dropped only under cap pressure, deterministically.

Retention now also reserves the newest official Core rows — 20 Omarchy News and 3 Omarchy releases — before the rest of the protected lane competes for the 500-event bound. Core news depth is a product decision again rather than a side effect of marketplace growth, which has gone from 2,121 listed plugins on 2 September to 3,963 on 22 September.

Local state schema remains v13 and no migration is required; upgrading changes no existing reading decision. Feed schema remains v2, insights and setup-news remain v1, and the helper protocol remains v1. Front Page composition, significance, curation, event identity, timestamps, and ordering are unchanged.
