# Omarchy News Radar 0.5.0

Status: local candidate; not published.

The published release remains 0.4.16. These notes describe the local implementation being validated; they do not announce a release, marketplace update, or deployed web edition.

## A brief you can finish

- Front Page holds up to five story groups chosen from unread source facts and local filters. Critical and reviewed notable stories, official Omarchy changes, enabled-plugin activity, and a discovery can earn a place. Popularity metrics do not affect selection, and routine verification changes do not consume a slot on their own.
- Updates for one plugin share a group with access to every original source. Selecting its headline reads only that representative event; **Mark group read** explicitly reads the included updates.
- The brief persists across closing, reopening, and refresh. Later arrivals remain available in other sections and through **New briefing**. **Mark briefing read** affects only the persisted brief; skipped stories remain unread, and a finished brief stays finished until explicitly replaced.
- If an included event leaves the rolling live edition, the reader explains that expiry instead of treating it as a read. Source sections keep their full local search, filters, and finite pagination.
- `F6` enters or leaves briefing controls; `Tab` and `Shift+Tab` traverse their actions. Expanded group history supports Up/Down, Home/End, and Enter to open the selected original source. Normal section navigation remains available outside this mode.

## A deliberate first visit

- **Browse current stories** leaves the backlog unread. **Start from today** explains and marks the displayed edition read while keeping its stories available to browse, preserving saves, preferences, and explicit unread choices.
- A changed edition requires reviewing that choice again. The welcome screen and its browse action do not automatically read the first story.
- Existing reading state migrates from schema v1–v11 to v12 with supported state preserved and the welcome choice already complete. After onboarding, fresh-open and deliberate selection retain their one-event read behavior.

## Delivery and discovery

- Desktop feed requests negotiate gzip; the shared HTTP reader decodes it while independently limiting transferred and decompressed bytes. Unsupported encodings, corrupt or truncated streams, and either size overflow fail without replacing a valid feed cache or its validators. Conditional refreshes and uncompressed responses remain supported.
- The generated web edition explains the desktop reader, links directly to the official marketplace listing, keeps RSS easy to find, and includes fixed-origin page and social metadata. It preserves original source links, escaped content, a restrictive static security policy, and the existing publication file paths.
- Public installation instructions now appear before development instructions in the README. The existing walkthrough and marketplace preview show the released reader, not the candidate's new screens.

## Compatibility and release evidence

- Manifest, panel, and Python runtime identity are 0.5.0. Feed schema stays v2; local state becomes v12. Read state, saved stories, preferences, and installed-plugin matching remain on the device.
- The fixed Forge publication URL and source allowlists remain unchanged. This candidate adds no account, telemetry, remote personalization, AI summaries, or automatic plugin installation.
- Focused offline tests cover briefing selection, migration, exact read scope, first-use races, gzip bounds, static acquisition links, and truthful candidate documentation. Full source gates, exact-candidate Plugin Lab evidence, refreshed release media, and public installation verification must be recorded in the release evidence before publication.
- The retained public-install scenario targets released 0.4.16 and state v11. It does not establish 0.5.0 public installation coverage. The candidate has not been pushed, tagged, released, promoted in the marketplace, or deployed by this local change.

See the [release contract](../RELEASE.md) for publication gates and evidence requirements.
