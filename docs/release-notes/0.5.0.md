# Omarchy News Radar 0.5.0

Status: local candidate; not published.

The published release remains 0.4.16. This expanded candidate makes Radar useful both for catching up and for deciding what to explore next. This candidate passed local source and disposable desktop verification and is installed for owner testing. It is not a marketplace update or a deployed web edition.

## A home worth opening

Front Page brings together a finite briefing, documented changes for your setup, reviewed workflow ideas and project discoveries. Finishing the brief leaves those other reasons to return. Opening Home does not read a hidden story; choose a briefing card to enter its reader.

Empty sections, searches and Saved show one useful recovery action across the reading area. The inspector and story buttons appear only when there is a story to act on. Detail links follow their visible order with Tab, and a new detail opens at its heading.

The brief holds at most five source-linked groups and survives refresh, close and reopen. Updates for one project stay grouped with their individual sources. Mark group read and Mark briefing read affect only the retained event IDs. New briefing explicitly chooses another selection, and skipped stories remain unread. Expired stories are disclosed, not counted as read.

## Understand what changed for your setup

My setup connects locally enabled plugin versions to documented public releases. Details show the relevant source notes and changes, with direct original links. Strict version matching distinguishes build variants while handling conventional v-prefixed release tags. Unknown or incomparable versions stay unknown; documented coverage is explicitly incomplete. Radar does not install, update or enable other plugins.

An optional shared insights feed carries bounded source facts. Release-note coverage begins with seven reviewed repositories; some authors do not publish GitHub releases, which is a valid empty state. A broken companion response cannot replace good cached news. Search and mute choices preserve source context for reachable stories, and historical repository checks prevent a story from inheriting another owner's release notes.

## Discover something useful

Three initial documentation-based workflow ideas cover arranging a workspace, a focused session and moving a capture into another app. Each explains what the projects do, links to its authors and records when its documentation was reviewed. Suggestions do not pretend to be compatibility tests or security endorsements.

Project, source and stable creator Follow/Mute controls work locally. Following & muted exposes every saved choice and its clear action. These choices influence future briefings and source browsing; an existing brief keeps its membership, and Saved remains available. Setup versions, preferences, search, saves and reading history never leave the device.

## A calmer opening

Radar prepares an exact floating-window rule and bounded geometry before its first visible frame. Saved placement is separate from reading state and clamped to usable connected-monitor space. Re-summoning preserves the selected item and focused control. Temporary rules expire and normal close/cancel paths remove them.

The window remains movable, resizable, maximizable and part of normal Alt+Tab. Real desktop evidence must cover initial mapping, neighboring-window geometry, resize/reopen, keyboard focus and cleanup; settled screenshots alone are not acceptance.

Changing text size or monitor layout while Radar is open also refits the floating frame when needed, preserving valid user placement and focus. Compact reader actions scroll with the content so large text leaves space to read.

## Public pages and delivery

The public reader gains individual story pages, workflow pages and weekly editions with original source links and escaped sharing metadata. The Laravel publication integration retains older shared pages within explicit storage bounds. It stages successor continuity before promotion and recovers interrupted publication.

HTTP serving negotiates gzip or identity, uses representation-specific ETags and Vary, handles HEAD/304 without a body, refreshes mutable CSS and counts the actual encoded response bytes. The plugin preserves separate encoded and decoded input bounds. These are local server source changes; production Forge/nginx behavior requires deployment verification.

## Safer upgrades and a maintainable codebase

First-use choices remain explicit: Browse current stories preserves the backlog; Start from today applies only to the displayed edition and preserves saves and explicit unread choices. State v13 preserves supported v1–v12 reading state and preferences. Existing readers retain their onboarding choice and existing brief.

Feed schema remains v2 for older clients. The richer public data uses an independent insights-v1 companion. Python domain, feed, reading, migration and publication responsibilities are split into named modules; QML separates lifecycle, session, navigation and presentation responsibilities.
