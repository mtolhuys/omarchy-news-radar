## Regression coverage

- `make test` passed all 342 tests on 17 September 2026.
- `tests.unit.test_plugin_update` uses temporary real Git repositories and proves:
  - a newer commit with the same manifest version remains `current` and cannot be applied;
  - the same-version result remains quiet for a dirty checkout even when the updater binary is unavailable;
  - only a strictly greater bounded `major.minor.patch` version becomes `behind`;
  - malformed versions fail the remote check closed and a locally greater version is never downgraded;
  - dirty and divergent checkouts block a real greater release;
  - a same-version server commit landing between inspection and official apply does not create a false failure.
- `make validate` passed Python compilation, tracked-English and placeholder policy, JSON/schema/generated feed/paired-manifest/workflow validation, ShellCheck for all scripts, and desktop-file validation. QML lint remains delegated to the exact Omarchy source or disposable lab because `OMARCHY_SOURCE` was not set for the host validation.
- `make feed-fixture` and `make site` produced valid bounded offline artifacts.

## Runtime contract

- `activation-upgrade.sh` now extends the ordinary official-updater guest journey with a same-version remote commit after the candidate is installed. It dirties only the disposable installed checkout and requires `update-status` to remain `current`, with distinct installed/available commits and equal installed/available release versions.
- No host plugin installation, shell restart, Hyprland reload, or personal configuration mutation is used as evidence.
- `./bin/lab doctor` on 17 September 2026 confirmed the selected Omarchy 4.0.3 ISO checksum and publication-ready lab repositories, but returned `not ok - /dev/kvm is unavailable`; no VM behavior is claimed from that host.

## Safety and compatibility

- Both manifests are read from explicit commit objects and bounded to 64 KiB before JSON parsing.
- Plugin identity and strict three-part release versions are required before comparison.
- Same-version commits bypass cleanliness, topology, and updater availability because there is no client release to apply.
- A real newer release still requires a clean fast-forwardable checkout and delegates mutation to `omarchy-plugin-update`.
- Feed, insights, setup-news, and private-state schemas are unchanged. No new dependency, network origin, permission, daemon, or configuration mutation is introduced.
