## Missed contract and root cause

Version 0.1.5 correctly detected and safely migrated the exact old block, but it required the user to notice and click a second **Update shortcut** action after already running the normal plugin updater. The updater itself only fast-forwarded the checkout, validated it, and rescanned the shell; it never invoked the migration helper. The retained `toggle` binding therefore kept closing an obscured Radar until the extra action ran.

The host audit reproduced that exact state: released commit `7d8df175009b24060387623e01c2528be02dbe4c` and manifest 0.1.5 were installed; the current bar and desktop entry used `summon`; the personal managed block still contained `toggle`; `hyprctl binds -j` exposed one live Radar action; and the helper classified it as `owned-legacy`. This excluded a failed update download, stale QML generation, duplicate activation, and a current bar route defect.

## Repair and ownership boundary

Omarchy's official updater ends a successful update with `omarchy-shell shell rescanPlugins`. Version 0.1.6 uses that supported boundary: the new bar generation invokes `news-radar-shortcut migrate-owned-legacy` once after its component is ready. The command cannot install a free chord. It returns without mutation for current, free, personal, edited, conflicting, multiple, symlinked, or ambiguous states and reaches the existing migration only for one byte-exact 0.1.3 Radar-managed block, one complete marker pair, and one matching live Radar action.

The successful path preserves every surrounding byte, creates a private backup, writes atomically, reloads Hyprland, requires no configuration errors and one live Radar action, and restores the complete original on failure. The panel's visible action remains a retry if automatic validation cannot complete. Fresh shortcut setup remains explicit, and the separate `Super+Shift+N` Editor action is never modified.

## Product and regression proof

The permanent upgrade journey installed released 0.1.3, created its managed shortcut, and reproduced the obscured-window close through both the real newspaper and compositor shortcut routes. It then staged the exact 0.1.6 candidate and ran only `omarchy-plugin-update io.github.mtolhuys.news-radar --yes`. Before opening Radar or clicking a migration control, it proved:

- helper classification was already `owned`;
- `bindings.lua` contained `summon` and no legacy `toggle` command;
- a private Radar backup existed;
- `hyprctl configerrors` was empty;
- no Radar client had been opened as a side effect.

The real QMP `Super+Alt+N` route then opened Radar, raised it after another ordinary window obscured it, and kept exactly one focused window. The actual newspaper did the same after another obstruction, and a foreground repeat kept Radar open. Exact removal released the chord.

The independent fresh-install journey revalidated the complete product: conflict-free shortcut install/removal, Apps entry, default newspaper, closed-panel unread adoption, 15-minute success/five-minute failure cadence, image and metric projection, exact per-story and filtered-section reading state, dense-list viewport-edge re-anchoring, arrow-key/Enter finite pagination, source opening, stale/offline/invalid/partial preservation, light/dark/narrow/200-percent-text checkpoints, foreground/obscured/rapid activation, normal window management, same-path runtime update, disable/re-enable, and clean removal.

## Marketplace preflight and boundaries

Version 0.1.6 retains the same single root plugin ID, paired `panel`/`bar-widget` entry points, manifest schema, source-wide identity, public repository, and Quattro dependency boundary. It adds no install hook, package manager, privilege escalation, service, daemon, bundled executable, remote build, or download-and-execute path. The only new runtime command calls the already-bundled shortcut helper with one fixed literal subcommand and a fail-closed classification.

- Marketplace maintainers still control approval and deployment; a valid update request cannot promote itself.
- The previous marketplace snapshot remains authoritative until the final exact 0.1.6 commit passes compatibility validation, the Automated Security Baseline, maintainer approval, testing, and deployment.
- Automatic migration is limited to a block created by Radar's earlier explicit shortcut setup; it is not authority to install a fresh shortcut or rewrite arbitrary user configuration.
- Marketplace verification remains exact-commit compatibility and security-pattern evidence, not a security audit.
