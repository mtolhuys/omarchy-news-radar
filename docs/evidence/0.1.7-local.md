## Root cause and repair

Released 0.1.6 treated pagination and per-story read refreshes like section resets. Expanding the model restored an older `storyViewportAnchorIndex`, while a read-state projection could overlap the keyboard animation. Both paths wrote `contentY`, producing the visible post-load jump and oscillation.

The live publication workflow also started every scheduled collection from the same committed source snapshot. Its uploaded successor was never restored, so old marketplace differences repeatedly received the current run time and appeared new. The Front Page then injected three historical Core releases after already selecting the newest release.

The candidate gives every projection explicit reset or preserve semantics. Pagination and read-related projections retain the live viewport, stable event selection, and exact visual anchor; context changes still reset deliberately. A monotonic viewport revision prevents stale deferred scroll callbacks from repositioning a newer selection.

Publication now restores the exact source artifact from the latest successful deployment and fails closed without it. Snapshot v2 resets contaminated discovery-only history from a fresh current source baseline, deterministic event IDs preserve first-observation timestamps, local live collection advances a private baseline only after import, and Front Page selects only one official release.
