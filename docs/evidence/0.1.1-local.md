## Refresh, relevance, and pagination proof

The root freshness defect was a local-edition early return that prevented every network refresh after `make local-latest`. The client now always validates the fixed hosted candidate, preserves an equal or newer owner-built edition, and atomically adopts a newer published edition. Network, malformed, oversized, and downgrade candidates still preserve the last-known-good cache.

State v8 removes the nonfunctional interests control, CLI argument, projection branch, and current-state field. Migration validates then discards the old v2-v7 array while preserving display preferences, section names, filters, saves, and the complete v7 read-override map. `For You` now has one honest rule: exact enabled-plugin IDs detected locally.

The rendered local Lab scenario proved all of the following:

- Refresh exposes an animated process-bound indicator while cached stories stay readable, then clears it on completion.
- Down from the last visible story focuses the rendered **Load more** control.
- Physical Return expands a 12-story page to 24, preserves the prior story selection, and does not mark a newly revealed story read.
- The next Down selects the first newly revealed story; Up from the focused control returns to the final prior story.
- The Settings screen and helper help contain no interest input or argument, and current private state contains no interest field.
- Offline, invalid, oversized, partial-source, empty, long-text, high-scale, narrow, dark, and light states retain their documented recovery and contrast behavior.

The exact public-clone scenario independently installed the GitHub commit, opened it through both the managed Apps entry and `Super+Alt+N`, loaded the 91-event Pages edition, persisted only the selected story as read, closed without an owned helper, and removed the shortcut, launcher, and plugin cleanly.
