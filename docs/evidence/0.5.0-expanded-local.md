# Expanded 0.5.0 local verification

This record concerns the expanded D058–D060 candidate, not the earlier briefing-only implementation. Public Radar remains 0.4.16. No public push, tag, marketplace promotion or Forge deployment is established by this evidence.

## Source and server

The frozen Radar source gates passed on 5 September 2026: 275 unit/integration tests, Python compilation, schema/fixture/manifest/workflow validation, ShellCheck for fifteen scripts, desktop-file validation, and QML lint against the selected current Omarchy source. Offline fixture and static-site generation also passed. The network integration cases use only a localhost fixture server; the default sandbox denied socket creation, so the complete suite was rerun with loopback permission and passed.

The homepage feature branch contains the tested server changes in commits `5cdf77b35dbaa501d3bdad492860f5c249e37680`, `3e6a988` and `cb59cca`. Its tree matches isolated server commit `81655ceeffb5bf3ad3ab0d7b0b7c9d3a2372c8af`. The final isolated full suite completed at 20:29:49 UTC with 120 tests and 1,009 assertions, no failures or skips. Pint and the unchanged Vite frontend build passed. Two pre-existing PHP 8.5 PDO constant deprecations remain. Tests used an in-memory database and did not change the homepage's real database or environment files.

Server tests execute the actual Python publisher and serve every generated artifact. A second generation removes a story and workflow and advances the week; previously shared URLs remain available. Recovery covers interruption around promotion, a partly deleted committed backup, and unsafe recovery material. Directory aliases redirect to trailing-slash URLs so browsers resolve nested styles and navigation correctly. HTTP coverage includes encoding quality values, identity/gzip validators, conditional precedence, HEAD/304, private representation-cache bounds and encoded response-byte accounting.

The measured real feed was 1,083,465 identity bytes and 112,543 gzip bytes. One hundred bodyless conditional gzip responses used approximately 1.4147 seconds of CPU before representation caching and 0.1322 seconds after. This measures the isolated response layer, not production requests per second or total Forge capacity. Proxy behavior still needs verification when deployment is authorized.

## Independent review corrections

Review found and corrected loss of retained rich notes during optional fetch failure, code examples being extracted as changes, ambiguous historical repository attribution, missing workflow primary links, detail lookup disappearing under search/mute, misleading local-candidate update warnings, and built-in shell components appearing as unidentified plugins. Source tests cover these boundaries.

Optional image requests are deduplicated and limited to four concurrent inspections with a 60-second queue budget; queued previews are omitted when the budget expires. Each running request still has its ordinary timeout. Body retrieval uses available-byte reads so a slow body cannot hide the deadline while filling a large buffer; virtual-clock tests cover identity, gzip and late EOF. Python's internal header/chunk framing still uses socket inactivity timeouts, so this is not a universal hard wall-clock deadline across every protocol phase.

## Desktop acceptance

The first pre-refactor opening run confirmed floating placement from the first mapped sample, unchanged neighboring-window geometry, repeat-summon focus preservation and resize/reopen placement. That evidence applies only to its preliminary snapshot and does not establish acceptance of the subsequent QML decomposition.

The decomposition exposed a fatal duplicate search signal that static QML lint missed. The signal was corrected and a mandatory declaration-collision gate was added. Controller IDs were also made distinct from component input names. A subsequent cold-click failure was traced to the VM test's absolute pointer retaining a stale coordinate after the compositor warped its cursor. The scenario helper now sends a distinct, acknowledged pointer movement before clicking; no product routing workaround was needed. The final expanded interface is awaiting its complete disposable desktop journey; daily-desktop installation must wait for that result.
