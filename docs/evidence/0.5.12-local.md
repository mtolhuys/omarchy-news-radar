# 0.5.12 notify-only update evidence

Status: released candidate under marketplace verification.

## Blocker

Marketplace reviewer HANCORE-linux, issue #6193, 2026-09-22T23:47:23Z, at `ba3482402cf7bbc1a7ec6ebb513c58dbf61ac8eb`: `radar/plugin_update.py` can fetch and install a newer mutable remote HEAD outside the exact reviewed snapshot; keep update checking notify-only and do not execute installation until the target commit has separate marketplace verification.

The finding was accurate and predates 0.5.11. Since 0.5.8 (D069) the panel's **Update plugin** control ran `news-radar-client update-apply`, which ran `omarchy-plugin-update io.github.mtolhuys.news-radar --yes` and fast-forwarded the installed checkout to whatever the repository's default branch named at that moment. D069 constrained *how* that install happened — strict versions, clean fast-forward, the official updater — but nothing tied the installed commit to the commit the marketplace verified.

## Repair (D074)

- `radar/plugin_update.py` is notify-only. `apply_update`, `UPDATER_NAME`, `_resolve_updater`, `_dirty` and `_can_fast_forward` are removed. `inspect_update` keeps the D069 release boundary and reports `canApply: false` on every path; a newer release yields `behind` with a plain-text message pointing at the Omarchy plugin marketplace.
- The CLI no longer accepts `update-apply`.
- The panel's **Update plugin** and **Retry update** controls and the updating/updated/failed apply states are removed; the masthead notice is text only.
- `scripts/validate_repo.py` now fails if the update helper names `omarchy-plugin-update`, defines `apply_update`, resolves an updater, or passes a mutating Git subcommand, and if the panel reintroduces an install command, action or button.
- The owner-run `make local-latest` synchronization is unchanged; it installs only from a clean local checkout, refuses any non-local origin, and the validator already enforces that refusal.

## Verification record

- `make test`: 350 tests passed. The update suite was rewritten from 11 to 8 tests: the apply and dirty/divergent-blocking tests encoded the removed behaviour.
- Every subprocess the check starts is recorded and must be a read-only `git` subcommand (`rev-parse`, `fetch`, `cat-file`, `show`); the installed `HEAD` and worktree must be unchanged afterwards, for clean, dirty and divergent checkouts.
- Mutation check: restoring the released 0.5.11 `radar/plugin_update.py` and `radar/cli.py` fails `test_a_newer_release_is_reported_and_never_installed`, `test_can_apply_is_false_for_every_checkout_shape` and `test_the_helper_exposes_no_install_entry_point`. Appending an `omarchy-plugin-update` literal to the helper makes `make validate` fail with `plugin update check must stay notify-only`.
- `make validate`: all checks passed, including ShellCheck for 17 scripts and `qmllint` against the lab's pinned Omarchy source.
- `tests/lab/update-notice.sh`: passed in the disposable Omarchy 4.0.3 guest, run `omarchy-iso/test-runs/omarchy-4.0.3/runs/20260923-092029`, 6 screenshots. The candidate was installed from a guest-local origin at 0.5.12; the origin's default branch then advanced to an unverified `99.0.0` commit. Opening Radar produced the masthead notice `News Radar 99.0.0 is available. Install it through the Omarchy plugin marketplace once that release is verified there.` After a further wait the installed `HEAD`, manifest version and worktree were unchanged, `news-radar-client update-apply` was refused, `update-status` reported `behind` with `canApply: false` and no `updater` field, and the journal showed no updater run.
- `tests/lab/briefing.sh`: passed on this candidate, run `20260923-092240`, 26 screenshots, confirming the masthead change did not disturb the reader, briefing, first-use, theme or layout journeys.

## Compatibility

- Helper protocol remains v1 (D070): a command and a field were removed without changing the response envelope. `canApply` is kept and always false, so an older panel paired with this helper cannot offer an install.
- Local state schema remains v13; feed schema remains v2; insights and setup-news remain v1.
- No new network origin, dependency, permission or daemon.
