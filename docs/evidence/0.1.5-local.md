## Root cause and repair

Version 0.1.4 correctly changed its source templates from `toggle` to `summon`, but a normal Omarchy plugin update intentionally runs no repository hooks and therefore does not rewrite the user's existing `bindings.lua`. A shortcut explicitly installed by version 0.1.3 remained the old live `toggle` action. The 0.1.4 helper recognized only its new byte-exact block, classified the retained old marker pair as ambiguous, and could neither migrate nor remove its own unmodified output. Fresh candidate acceptance installed only the new block and did not exercise this retained configuration.

Diagnostic run `20260902-002207` built released 0.1.3 and 0.1.4 as consecutive commits in a guest-only local origin. It reproduced the background-window close through the 0.1.3 newspaper and shortcut, fast-forwarded through the real Omarchy updater, proved the retained shortcut still closed Radar, and separately proved the loaded 0.1.4 newspaper raised and kept the obscured window open. This excluded duplicate pointer delivery, a current bar-source defect, and a QML focus race.

Version 0.1.5 adds an `owned-legacy` classification only for one exact 0.1.3 managed block, one complete marker pair, and one matching live Radar action. Panel opening performs only a read-only status check. The rendered **Update shortcut** action is explicit consent to replace that exact block with the current `summon` block. Migration preserves every surrounding byte, creates a private backup, writes atomically, reloads Hyprland, requires no configuration errors and one live Radar action, and restores the complete original on failure. Exact current and legacy blocks are removable; personal, edited, multiple, conflicting, symlinked, unowned, or otherwise ambiguous cases remain refused with no force path.

## Marketplace preflight and boundaries

The current marketplace update contract requires the existing exact plugin ID and repository root, the full 40-character current upstream commit, unchanged source-wide plugin identity, Quattro compatibility, a complete static Automated Security Baseline, and explicit maintainer approval before atomic promotion. Version 0.1.5 retains one root plugin with the same ID and paired `panel`/`bar-widget` entry points. It adds no install hook, package manager, privilege escalation, service, daemon, bundled executable, remote build, or download-and-execute path. Shortcut migration is an explicit local user action and marketplace verification remains an exact-commit compatibility/security-pattern check, not a security audit.

- Marketplace maintainers control approval and deployment; opening a valid request cannot promote the snapshot by itself.
- The previous marketplace snapshot remains authoritative until the exact 0.1.5 commit passes validation, baseline, approval, testing, and deployment.
- Omarchy's mutable upstream install/update commands remain separate from marketplace exact-commit verification.
- Normal plugin removal preserves cache, reading state, and saves. Explicit shortcut and launcher removal remain intentional owner actions performed while the checkout exists.
